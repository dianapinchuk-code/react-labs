# ЛР-10. Структури папок

Ці таблиці заповнюєте ви: рядок «Де живе кошик» після кожної структури
(§4.3–§4.6) і «Вибір структури» наприкінці (§4.7). Рядок «Пакет» — лише якщо
виконуєте додаткове завдання §4.9. Як рахувати теки, описано в інструкції,
§4.2.

## Де живе кошик

У яких теках лежать шість файлів кошика: сховище, `useCart`,
`AddToCartButton`, `CartLine`, сторінка кошика й шапка з лічильником.
«Тек» — скільки їх, «Теки» — їхні шляхи через кому.

| Структура                  | Тек | Теки                                                                                |
| -------------------------- | --- | ----------------------------------------------------------------------------------- |
| За типом файлів (§4.3)     | 4   | src/store, src/hooks, src/components, src/pages                                     |
| За маршрутами (§4.4)       | 5   | src/shared/store, src/shared/hooks, src/shared/components, src/routes/cart, src/app |
| За функціональністю (§4.5) |     |                                                                                     |
| FSD (§4.6)                 |     |                                                                                     |
| Пакет (§4.9)               |     |                                                                                     |

## Вибір структури

Описи проєктів, з чого обирати і як пояснити вибір — в інструкції, §4.7.
«Чому»: що в проєкті важливо і чому обрана структура для цього підходить.

| Проєкт                             | Структура                   | Чому                                                                                                                                                                                                                        |
| ---------------------------------- | --------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1. Прототип на хакатоні            | За маршрутами               | Проєкт невеликий і має бути зібраний швидко без складних правил шарів, але трьом розробникам зручно взяти по 1–2 окремі екрани без конфліктів у коді, а за перемоги таку базу легко масштабувати далі.                      |
| 2. Блог і документація на Next.js  | За маршрутами               | Сторінок багато (40), але вони незалежні й майже нічим не діляться, окрім шапки й підвалу в `shared/`; до того ж така структура природно збігається з маршрутизацією Next.js.                                               |
| 3. Адмінка для бариста             | За функціональністю         | У проєкті середнього розміру (15 екранів) чітко виділяються незалежні бізнес-напрями (замовлення, склад, зміни), а спільними є лише базові UI-елементи; структура за фічами ізолює кожну область без зайвої складності FSD. |
| 4. Інтернет-магазин кави           | Feature-Sliced Design (FSD) | Проєкт великий і довготривалий, над ним працюють три команди, а бізнес-блоки (кошик, картка товару) використовуються на багатьох сторінках; жорсткі шари та публічні API (`index.js`) захищають від хаотичних залежностей.  |
| 5. Три застосунки мережі кав'ярень | Пакети за Надією Макаревич  | Код дизайн-системи та кошика ділять одразу три різні застосунки (сайт, кіоск, адмінка), тому винесення спільного в локальні пакети з обмеженим `exports` у `package.json` захищає межі на рівні самої платформи.            |
